# Design Intent

Зафиксировано до первого изменения приложения: **2026-08-06**.

## Контекст

**Предмет:** desktop-интерфейс оператора для наблюдения за агентным запуском.  
**Аудитория:** разработчик, который одновременно читает transcript, оценивает риск команды и при необходимости останавливает выполнение.  
**Главная работа:** за 1–2 секунды понять «что происходит сейчас», затем по запросу увидеть команду, безопасные tool details, output и способ восстановления.

## Визуальная система

Палитра из 6 опорных цветов:

- `#0B0F12` — фон рабочей области;
- `#151A20` — поверхности и активный блок;
- `#E5EBF0` — основной текст;
- `#8D99A6` — вторичный текст и cancelled/pending hierarchy;
- `#78BFA8` — running/success accent;
- `#D17A7A` — error/recovery accent.

Границы и hover-состояния выводятся через прозрачность этих же цветов, без расширения палитры.

Типографика использует только уже имеющиеся в проекте system/monospace stacks:

- system sans — навигация, summary, labels;
- monospace — команды, пути, output, elapsed time;
- 12–13 px — основной плотный transcript;
- 11 px — metadata/status;
- 14–16 px — текущая операция и локальные заголовки, без oversized hero.

Плотность: 4/8 px rhythm, строки событий примерно 30–36 px в свёрнутом виде, подробности добавляют высоту только по запросу.

Motion: 120–160 ms, только opacity/transform для появления/раскрытия; running glyph допускает спокойную пульсацию. При `prefers-reduced-motion: reduce` анимация отключается.

## Signature element

Вертикальный **activity rail**: слева семантический glyph/status, в центре безопасный summary, справа elapsed/status. Текущая операция получает единственную усиленную поверхность. Команды и tool details раскрываются внутри той же строки, а не в отдельной карточной галерее.

## Самокритика до реализации

- Не превращать каждое событие в отдельную rounded card; rail и типографика должны нести основную структуру.
- Не использовать неон, glow, gradient text, scanlines, Matrix green или «AI dashboard» clichés.
- Не делать thinking-copy похожим на внутренний монолог: показывать только итоговый безопасный summary/approach.
- Не анимировать completed history; движение допустимо только для текущей операции и раскрытия по запросу.
- Не скрывать ошибку одним красным значком: рядом нужен текст, следующий шаг и Retry/Copy details.
- Не автоскроллить, если пользователь читает историю.
- Не плодить параллельный state manager: activity model должен подключаться к существующему preview flow и оставаться заменяемым будущим OMP backend.

## Самокритика после реализации

- Activity rail остался частью transcript, а не отдельным dashboard: на 1280×800 одновременно видны prompt, текущая операция, 5-step summary и Stop.
- Running state использует только одну усиленную строку; completed history остаётся спокойной и компактной.
- Error review показал причину, exit code, ограниченный output и следующий шаг без вытеснения composer за пределы desktop shell.
- На 760×720 длинный path переносится, controls остаются доступны без горизонтального document overflow.
- На 1920×1080 контент не растягивается на всю ширину: transcript сохраняет читаемую меру и TUI-плотность.
- Mouse/keyboard QA выявил два дефекта уже после первой реализации: boolean settings не менялись pointer-кликом, а install dialog не получал гарантированный focus. Оба исправлены в source и повторно проверены.
- Случайные проценты, бесконечные логи, декоративный glow, glassmorphism и чужой branding не появились.
