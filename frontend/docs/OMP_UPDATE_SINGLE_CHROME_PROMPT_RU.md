# Промт для обновления OMP без двойного chrome

Используй этот промт при каждом обновлении runtime, shell или интеграции OMP в ma-hi-ko.

---

Обнови OMP-интеграцию в существующем Electron-приложении **без создания второго слоя интерфейса приложения**.

## Обязательные ограничения

1. В приложении существует ровно один визуальный chrome: React-workbench ma-hi-ko.
2. Не добавляй в renderer вторую строку меню `File / Edit / View / Window / Help`, второй title bar, второй status bar или дублирующий toolbar OMP.
3. Системное меню Electron должно оставаться скрытым:
   - `autoHideMenuBar: true`;
   - `mainWindow.setMenuBarVisibility(false)`;
   - `Menu.setApplicationMenu(null)`.
4. Не используй `window.open()` и не создавай дополнительный `BrowserWindow` для ветки, дерева файлов, pull request, review, терминала или настроек. Эти поверхности должны открываться как закрываемые внутренние панели, dialogs или tool views внутри основного окна.
5. OMP передаёт данные через существующие typed IPC/runtime contracts. Он не должен монтировать собственный независимый desktop shell поверх React-workbench.
6. Модель, reasoning, контекст и состояние OMP показываются только в composer/status surface. Не дублируй их в правой review-панели.
7. Левая панель остаётся навигацией по чатам, проектам, изменениям, задачам, `/MCP` и скиллам. Правая панель остаётся review/diff surface.
8. Новая функциональность обязана переиспользовать текущие компоненты, CSS tokens и keyboard/focus conventions; не добавляй UI-библиотеки без отдельного обоснования.
9. Перед завершением проверь мышью и клавиатурой: открытие/закрытие каждой внутренней панели, Escape, восстановление фокуса, отсутствие второго меню и отсутствие новых окон операционной системы.

## Критерии приёмки

- На скриншоте всего приложения нет двух рядов `File/Edit/View` или двух title bars.
- В Electron DevTools `BrowserWindow.getAllWindows().length` остаётся равным `1` при открытии всех внутренних инструментов.
- В renderer отсутствуют вызовы `window.open`.
- В main process отсутствуют новые `new BrowserWindow(...)`, кроме создания главного окна.
- Ветка, дерево файлов и pull request открываются и закрываются внутри `.workspace-main`.
- `npm run typecheck`, `npm test`, `npm run build` и browser interaction QA выполнены; реальные ограничения среды записаны без маскировки.

Не копируй чужой брендинг или пиксельную композицию. Сохрани OMP Titanium-палитру, TUI-ритм, семантику и доступность ma-hi-ko.
