## UI Pro Max Search Results
**Domain:** web | **Query:** desktop application compact controls navigation status activity
**Source:** app-interface.csv | **Found:** 7 results

### Result 1
- **Category:** Navigation
- **Issue:** Back Behavior
- **Platform:** iOS/Android/React Native
- **Description:** Back navigation should be predictable and preserve state
- **Do:** Use navigation.goBack and keep screen state
- **Don't:** Reset stack or exit app unexpectedly
- **Code Example Good:** onPress={() => navigation.goBack()}
- **Code Example Bad:** BackHandler.exitApp() on first press
- **Severity:** Critical

### Result 2
- **Category:** Accessibility
- **Issue:** Dynamic Updates
- **Platform:** iOS/Android/React Native
- **Description:** Async status updates should be announced to screen readers
- **Do:** Use accessibilityLiveRegion or announceForAccessibility
- **Don't:** Update text silently with no announcement
- **Code Example Good:** <Text accessibilityLiveRegion="polite">{status}</Text>
- **Code Example Bad:** <Text>{status}</Text>
- **Severity:** Medium

### Result 3
- **Category:** Feedback
- **Issue:** Loading Indicators
- **Platform:** iOS/Android/React Native
- **Description:** Show visible feedback during network operations
- **Do:** Use ActivityIndicator or skeleton for >300ms operations
- **Don't:** Leave button and screen frozen
- **Code Example Good:** {loading ? <ActivityIndicator /> : <Button title="Save" />}
- **Code Example Bad:**  "<Button title=""Save"" onPress={submit} /> // no loading"
- **Severity:** High

### Result 4
- **Category:** Anti-Pattern
- **Issue:** No Gesture-Only Actions
- **Platform:** iOS/Android/React Native
- **Description:** Don't rely solely on hidden gestures for core actions
- **Do:** Provide visible buttons in addition to gestures
- **Don't:** Rely on swipe/shake only with no UI affordance
- **Code Example Good:** Swipe to delete + visible Delete button
- **Code Example Bad:** Only shake device to undo with no UI
- **Severity:** Critical

### Result 5
- **Category:** Navigation
- **Issue:** Modal Escape
- **Platform:** iOS/Android/React Native
- **Description:** Modals/sheets must have clear close actions
- **Do:** Provide close button and swipe-down where platform expects
- **Don't:** Trapping users in modal with no obvious exit
- **Code Example Good:** <Modal><Button title="Close" onPress={onClose} /></Modal>
- **Code Example Bad:** <Modal><View>{children}</View></Modal>
- **Severity:** High

### Result 6
- **Category:** Navigation
- **Issue:** Bottom Tabs
- **Platform:** iOS/Android/React Native
- **Description:** Bottom tab bar should have at most 5 primary items
- **Do:** Use 3–5 tabs and move extras to More/Settings
- **Don't:** Overloaded tab bar with many icons
- **Code Example Good:** Home/Explore/Profile/Settings
- **Code Example Bad:** Home/Explore/Shop/Cart/Profile/Settings/More
- **Severity:** Medium

### Result 7
- **Category:** State
- **Issue:** Preserve Screen State
- **Platform:** iOS/Android/React Native
- **Description:** Returning to a screen should restore its scroll and form state
- **Do:** Keep components mounted or persist state
- **Don't:** Reset list scroll and form inputs on every visit
- **Code Example Good:** <Tab.Navigator screenOptions={{ unmountOnBlur: false }}>
- **Code Example Bad:** <Tab.Screen options={{ unmountOnBlur: true }} />
- **Severity:** Medium
